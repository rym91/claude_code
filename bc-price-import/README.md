# BC PRICE IMPORT → шаблон PriceAndQuantityBC: цены превращаются в даты

## Что происходит

Часть цен в колонке `Your Price USD (Sell on Amazon, US)` лежит в файле не как
число, а как **дата**: `15.04.26`, `25.01.26`, `22.11.26`, `18.03.26`, `15/05/26`.
В строке формул у такой ячейки видно `28.01.2026`, а строка состояния показывает
для неё «Сума: 28.01.26» — то есть это настоящая дата, а не текст.

Причина не в Amazon и не в исходной таблице, а в локали программы, куда вы
вставляете. В украинской/русской локали разделитель дробной части — **запятая**,
а **точка — разделитель даты**. Поэтому при вставке в ячейку с форматом
«Загальний / General» Calc и Numbers читают:

| Скопировано | Как понимает программа | Что записалось |
|---|---|---|
| `15.04` | 15 апреля текущего года | дата `15.04.2026` |
| `25.01` | 25 января | дата `25.01.2026` |
| `22.11` | 22 ноября | дата `22.11.2026` |
| `19.99` | месяца 99 не бывает | число `19.99` ✅ |
| `54.94` | дня 54 не бывает | число `54.94` ✅ |

Отсюда и «через одну»: ломаются только цены, у которых **центы от 01 до 12**
и **доллары от 1 до 31**. Все остальные проходят нормально — поэтому проблема
и выглядит хаотичной.

Amazon потом ругается, потому что в поле цены приходит не `15.04`, а серийный
номер даты (`46127`) либо строка вида `15.04.2026`.

## Как вставлять, чтобы не ломалось

Порядок важен: формат колонки нужно задать **до** вставки. Если вставить, а
потом менять формат, число уже потеряно — вместо цены появится пятизначный
серийный номер даты.

### LibreOffice Calc (основной вариант)

Всё решается в одном окне: `Засоби → Параметри → Мови та локалі → Загальні`
(Tools → Options → Languages and Locales → General).

1. **Локаль: Англійська (США)**. Точка становится десятичным разделителем, и
   `15.04` вставляется как число. Шаблон Amazon этого и требует («Use ENGLISH
   to fill this template»).
2. Проверьте поле **«Шаблони розпізнавання дат»** (Date acceptance patterns)
   в том же окне. Для украинской локали там стоит `D.M.Y;D.M;D/M/Y`, и средний
   шаблон `D.M` — «день.месяц без года» — как раз и превращает `15.04` в дату.
   После смены локали на английскую поле само становится **`M/D/Y;M/D`**,
   и точка перестаёт быть разделителем даты.
3. Вставляйте через `Ctrl+Shift+V → Неформатований текст`. В окне импорта:
   **Мова: Англійська (США)**, снять галочку **«Розпізнавати особливі числа»**
   (Detect special numbers) — это отдельно запрещает распознавание дат.

Если локаль обязательно должна остаться украинской, сотрите `D.M` из шаблонов
и оставьте `D.M.Y;D/M/Y`. В дату цена больше не превратится, но при запятой в
качестве десятичного разделителя `15.04` станет **текстом**, а не числом. Для
Amazon это допустимо, но суммы и формулы по такой колонке работать не будут.

Поле шаблонов сбрасывается к значению по умолчанию при смене локали — сначала
меняйте локаль, потом сверяйте шаблоны. Настройка влияет только на новый ввод:
ячейки, которые уже стали датами, нужно чинить отдельно (см. ниже).

### Apple Numbers

В Numbers нет настройки локали внутри документа, он берёт её из системы:

- либо `Системні налаштування → Загальні → Мова та регіон → Регіон: США`;
- либо перед вставкой выделить колонку цены и поставить
  `Формат → Клітинка → Текст`, и только потом вставлять. Тогда `15.04`
  останется строкой `15.04` и в дату не превратится.

### Проверка после вставки

Формулой в свободной ячейке: `=ISNUMBER(G7)` / `=ISTEXT(G7)`.
Визуально: даты и числа оба прижаты вправо, так что «по выравниванию» не
проверить — смотрите строку формул, там у сломанной ячейки будет `15.04.2026`.

## Как починить уже испорченный файл

`fix_price_dates.py` — утилита рядом с этим файлом. Нужен Python 3 и `openpyxl`
(`pip3 install openpyxl`).

Посмотреть, что сломано (файл не меняется):

```bash
python3 fix_price_dates.py check PriceAndQuantityBC.xlsm
```

Починить в копию — даты обратно превращаются в цены, формат ячейки `0.00`:

```bash
python3 fix_price_dates.py fix PriceAndQuantityBC.xlsm -o PriceAndQuantityBC_fixed.xlsm
```

Записать колонку цен из источника, минуя разбор по локали. Скопируйте столбец
`BC PRICE IMPORT` из Google Sheets в обычный текстовый файл (одна цена в строке,
пустые строки сохраняют выравнивание по рядам) и:

```bash
python3 fix_price_dates.py paste PriceAndQuantityBC.xlsm prices.txt --column G
```

Скрипт сам находит лист `Template`, строку заголовков (по ячейке `SKU`) и все
колонки, в названии которых есть `Price` — то есть и `Your Price USD`, и
`Minimum/Maximum Seller Allowed Price`, и `Sale Price`. Колонки можно задать
руками: `--columns G,J,K`. Макросы `.xlsm` при сохранении сохраняются.

### Одно ограничение

`15.4` и `15.04` дают одну и ту же дату (15 апреля), поэтому обратно
восстанавливается `15.04` — вариант с двумя знаками. Для цен из прайса это почти
всегда верно, но если в источнике встречаются цены с одним знаком после точки,
такие строки нужно сверить с `BC PRICE IMPORT` вручную. Режим `paste` этой
неоднозначности лишён — он берёт значения прямо из источника.
